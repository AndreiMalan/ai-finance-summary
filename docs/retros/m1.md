# Retro — M1 (skeleton, config, Postgres, auth, limits, Vercel)

**What was built:** A FastAPI app deployed on Vercel (fra1) with Neon Postgres, env-driven settings, idempotent migrations and LangGraph checkpointer setup, Argon2 email/password login with signed cookies, demo account, login throttling, per-user run limits and a global daily LLM cap. Risk spikes confirmed the bundle fits (373/500 MB), SSE streams on Vercel, and checkpointer setup works on Neon.

**What went well**
- Per-task reviews caught real defects early: a deadlock between advisory locks and LangGraph's `CREATE INDEX CONCURRENTLY`, session locks through Neon's pooler, a demo-upsert account takeover, a pool leak on failed init.
- Testing against a real embedded Postgres (pgserver) made concurrency and lock bugs reproducible.
- Live preview verification found deploy issues (static builder, framework preset) before production.

**What caused rework**
- Plan code written before checking platform facts (Vercel 250 MB assumption, `buildCommand: ""`, functions preset) — fixed during T7.
- A "fail loudly" startup choice took production down on a short demo password (D-022).
- The final whole-branch review found a throttle bypass that per-task reviews missed (truncate-before-normalise across two modules) — cross-module invariants need an explicit check.

**Decision log entries:** D-016 … D-024 in `docs/decisions.md`.

**Pipeline improvement:** add a "platform facts" check (docs fetched, versions confirmed) to the Architect step before plans include deploy config, and require the final review to probe at least one end-to-end security flow (auth/limits) with a script, not only by reading diffs.
