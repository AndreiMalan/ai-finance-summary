# M8 — Web UI — Plan (lean, fast mode D-026)

> Two batches, one developer + one review each: **M8a** (shell, CSRF, wizard steps 1–4: tasks 1–4) and **M8b** (generate/review/history/diagnostics/preferences/KB/about: tasks 5–8). Worktree `D:/AI_Finance_summary-m8`, branch `m8-ui` from main after M7 is merged.

**Goal:** A modern, intuitive server-rendered UI over the existing JSON APIs and the M7 graph runner. Users create a report, pick sources, upload and map files, resolve validation issues and conflicts, watch generation live, review a draft with clickable citations and provenance, approve/reject/request changes, resume later, and inspect history and diagnostics (AC 39–43, 49, 51–59; brief §UI).

**Stack (existing, don't change):** FastAPI + Jinja2 templates (`src/statbrief/web/templates/`, `base.html`), HTMX 2.0.11 + Alpine 3.17.5 (vendored in `static/vendor/`), Tailwind 4.3.3 + DaisyUI 5.7.50. CSS is built with `npm run build:css` from `static/src/app.css` into the committed `static/app.css`. Rebuild and commit it whenever you add classes; Vercel does not build CSS. No SPA framework and no CDN scripts. Charts: one small vendored library is allowed (prefer Chart.js 4.x UMD via `npm`, copied in the `vendor` script). Pin it exactly in package.json.

**Design reference:** the approved mockup (light theme, left sidebar "My reports / New report / Knowledge base / Preferences / About", top wizard stepper 1 Sources · 2 Upload & map · 3 Validate · 4 Conflicts · 5 Generate · 6 Review). Read `docs/brainstorm.md` and the UI notes in `docs/spec.md`. Use DaisyUI components: steps, cards, tables, badges, alerts, modals and the timeline. The UI must be responsive down to 375 px, keyboard accessible, with visible focus and aria-live regions for progress.

**Constraints:** every page and partial is user-scoped (404 for others' reports); CSRF synchronizer tokens on **all** state-changing forms and HTMX requests, login and signup included (D-018). Use a per-session token in a hidden field plus an `hx-headers` meta for HTMX, and validate it in a dependency. JSON APIs called with `fetch` send the header. Never render raw cell values unescaped (Jinja autoescape stays on; no `|safe` on user/LLM content). Model-written prose is rendered as plain text, with paragraphs split on blank lines. Tunables go in Settings. Docstrings everywhere. Tests use FastAPI TestClient plus the pgserver fixture, with the graph run against fake models (M7 `GraphDeps`). No network. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## M8a

### Task 1 — Shell, CSRF, navigation (`web/csrf.py`, `templates/base.html`, `templates/partials/`)
- CSRF module, dependency and template global. Retrofit login, signup, logout and the upload APIs. Tests: missing/invalid token → 403; valid → OK; token rotates on login.
- App shell with sidebar, user menu, flash/toast area, the wizard stepper partial (steps show done/current/locked from the report status), and empty states.
- "My reports" list: status badge, last activity, a resume button that deep-links to the right step, and delete with confirmation.

### Task 2 — Step 1 Sources + Step 2 Upload & map
- Sources form: report title, indicators from `CATALOG` (grouped Eurostat/World Bank, with labels), regions (NUTS RO + EU from `regions.csv`, searchable), period from/to, consent checkbox for gap filling, optional "link uploaded indicator ↔ catalog code" pairs. Preferences pre-fill these (M7b `PreferencesRepo`).
- Upload: drag-and-drop with chunked upload (D-021) through the existing API, a progress bar per file, sniff rejections shown as friendly messages, the file list with delete, and template downloads.
- Preview grid (first N rows, sticky header, worksheet picker, header-row picker). Mapping panel: a role select per column with confidence badges, low-confidence highlighting, per-role picks, unit/multiplier fields, and "column documented?" toggles feeding the undocumented set. Saved through the mapping API.
- Tests: page renders for the owner and 404 for others; mapping save round-trip; rejection message shown.

### Task 3 — Step 3 Validate
- Issue groups (per kind, count, sample rows) with resolutions (fix value / exclude rows / accept). Show the rows an exclusion removes. Re-validate button. Normalize when no blocking issues remain. Show encoding/embedded-object warnings.
- Tests: issue resolution round-trip; normalize is blocked while issues remain.

### Task 4 — Step 4 Conflicts (and interrupt #1 UI)
- Render the M7 resolve interrupt payload: conflicts as side-by-side cards (source labels, values, relative difference, provenance links) with prefer / keep both / exclude; unit mismatches as info; failed API sources with "continue without X?"; low-confidence mappings with a link back to step 2. Submitting posts `Command(resume=ResolvePayload)` through the M7b resume route. Validation errors from a re-interrupt are shown inline.
- Tests: resume payload built correctly from the form; an invalid choice re-renders with the error.

**M8a done:** tests green; CSS rebuilt; report `.superpowers/sdd/m8a-report.md` with screenshots described (or saved under `.superpowers/sdd/shots/` if a headless browser is available locally; optional).

## M8b

### Task 5 — Step 5 Generate (live timeline)
- An SSE client (HTMX sse extension is vendored only if needed; otherwise ~40 lines of `EventSource` in Alpine) renders the M7b `SseEvent`s as a DaisyUI timeline: node name in human words, progress, retries and revisions. On `continue` it reconnects automatically (segmented run, AC 45); on `already_running` it shows a notice; on an interrupt it routes to step 4 or 6; on failed (fail_safe) it shows the last draft and the verifier feedback ("needs manual attention"). aria-live polite.
- Tests: the SSE route streams with a fake graph; the template maps every event type.

### Task 6 — Step 6 Review
- Draft view: title, executive summary findings, sections with paragraphs; each numerical claim highlighted, and clicking it opens a provenance drawer (metric formula, input observations → file/sheet/row or API series + URL, AC 49/56). Citations are grouped *Uploaded files / Public APIs / Reference documents* and passages show issuer, section and page. Caveats and acknowledged unknown columns are shown.
- A chart per indicator section (line chart of the series used, from observations; values only).
- Actions: Approve, Reject, Request changes (comment). Optional inline edit of paragraph text, re-verified by the graph before export. Resume via the M7b route.
- Tests: claim → provenance mapping; actions post the right `ReviewDecision`; escaping of LLM text.

### Task 7 — History, diagnostics
- History tab (`ENABLE_REPLAY`): checkpoint list (step, node, time, has draft), view a prior draft, and fork from a checkpoint with confirmation. Hidden when the feature is off.
- Diagnostics tab (AC 51): `run_events` table (kind, name, model, latency, tokens, errors) with totals; no prompt text unless `log_prompts` is on and the viewer owns the report.

### Task 8 — Preferences, Knowledge base, About
- Preferences: default regions, indicators, style and formats (PostgresStore via M7b), with a note that they are never used as data.
- Knowledge base: list shared docs (issuer, title, version, date) and the user's uploaded reference docs; upload a reference doc (.pdf/.txt/.md, M5 rules) which is indexed for this user only; delete own docs; a search box (retrieve) showing passages with method (vector/FTS) and scores.
- About: what the app does, data sources, and a clear note that ESMB and IRS reference documents are fictional demo material (D-006). Links to Eurostat/World Bank as the real APIs.
- Tests: KB upload visible only to its owner; search shows source metadata.

**M8b done:** tests green; CSS rebuilt; bundle measured; report `.superpowers/sdd/m8b-report.md`.
