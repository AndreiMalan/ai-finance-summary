# M6 — LLM Layer (LangChain) — Plan (lean, fast mode D-026)

> One developer, one reviewer. Starts after M3, M4 and M5 are merged into main (it consumes `ReportDraft` from M4, the retriever from M5 and API metadata from M3). Worktree `D:/AI_Finance_summary-m6`, branch `m6-llm` from main.

**Goal:** Every LangChain concept the brief requires, as working features with tests that need no API key: chat-model configuration via environment, reusable prompt templates, Pydantic structured output with malformed-output detection, LCEL chains, controlled tool calling with validated, user-scoped arguments and deterministic calculations, a redacting callback handler that logs model calls/tokens/latency/tools/retrieval/errors to Postgres, and the "unknown column meaning" guard (AC 28–30, 33–35, 51; brief §8A).

**Constraints:** Settings (+ `.env.example`): `llm_provider="openai"`, `llm_model` (default `gpt-5-mini` — verify the current OpenAI small model name from the langchain-openai docs and record it), `llm_temperature=0.2`, `llm_timeout_s=60`, `llm_max_retries=2`, `openai_api_key: SecretStr|None` (already added in M5 — reuse), `max_tool_rows=200`, `log_prompts=False` (debug mode; when False only template names/variable names are logged). Tests use LangChain fake chat models (`GenericFakeChatModel`, `FakeMessagesListChatModel`) and fake embeddings — never the network. Only summaries/selected rows go to the model (AC 35): never whole uploaded files. Migration **005** (`run_events`). ## Task 1 — Model factory (`llm/models.py`)
- `get_chat_model(settings, *, callbacks=None) -> BaseChatModel` via `langchain.chat_models.init_chat_model(f"{provider}:{model}", temperature, timeout, max_retries, api_key)`; raises `LLMNotConfigured` when no key (callers turn this into a friendly message).
- `get_embeddings(settings) -> Embeddings | None` (OpenAIEmbeddings with `check_embedding_ctx_length=False`; None without key) — M5's retriever already accepts None.
- Tests: provider/model read from Settings; missing key → LLMNotConfigured; fake model injectable.

## Task 2 — Prompts (`llm/prompts.py`)
- `ChatPromptTemplate`s: `DRAFT_PROMPT`, `INTERPRET_DATASET_PROMPT`, `REVISE_PROMPT` (verification feedback), `REVIEW_REVISE_PROMPT` (human comment). Variables: region(s), reporting period, metrics table (metric_id, value, unit, formula), significant changes, source metadata (file/sheet or API series + URL), retrieved passages (with citation labels), column descriptions, undocumented columns, style rules from the ESMB commentary guidelines.
- System rules (explicit): use only provided numbers; every number must be a `NumericalClaim` with `metric_id` or `observation_ids`; never interpret undocumented columns — list them in `unknown_columns_acknowledged`; cite passages by id; percentage points for rate changes.
- `render_context(...) -> dict` builds compact, deterministic inputs (no raw uploads; ≤ N metrics/passages from Settings).
- Tests: required variables present; no raw rows leak; snapshot of a rendered prompt.

## Task 3 — Structured output + LCEL chains (`llm/chains.py`)
- `build_context_chain(retriever_fn)` — `RunnableParallel` (retrieve passages ‖ format metrics) → `RunnableLambda(render_context)`.
- `build_draft_chain(model)` — `DRAFT_PROMPT | model.with_structured_output(ReportDraft, include_raw=True) | RunnableLambda(check_parsed)` returning `DraftAttempt(draft|None, raw_text, parse_error|None, usage)`; malformed/missing fields → `parse_error` (never raises into the graph).
- `build_revise_chain(model)` — `REVISE_PROMPT | …same tail` with verification feedback.
- Tests: valid fake output → ReportDraft; malformed JSON / missing field / claim without observation_ids → parse_error set; usage metadata captured when present.

## Task 4 — Tools (`llm/tools.py`)
- `build_tools(store: ObservationStore, metrics, catalog, user_id, settings) -> list[BaseTool]` (`@tool` with Pydantic `args_schema`):
  - `get_indicator_metadata(indicator_code)` (catalog + series meta; unknown → error message, not exception);
  - `list_available_metrics(indicator_code=None, region=None)`;
  - `query_observations(indicator_code, region, period_from, period_to, limit≤max_tool_rows)` — validated args, user-scoped store only;
  - `compute_metric(metric_id)` — deterministic recomputation (M4) — the model never does arithmetic.
- Invalid args → tool returns a validation error string (model can correct); permission violations impossible by construction (store is the user's report only).
- Tests: arg validation errors, limit clamp, compute_metric equals M4 result, tool-calling loop with a fake model emitting tool calls (`bind_tools`).

## Task 5 — Callbacks / observability (`llm/callbacks.py`, migration `005_run_events.sql`, Diagnostics data)
- `run_events(id, report_id, user_id, ts, kind (llm_start|llm_end|llm_error|tool_start|tool_end|tool_error|retrieval|node), name, model, latency_ms, prompt_tokens, completion_tokens, detail jsonb)`; user-scoped repo `RunEventRepo.add/list_for_report`.
- `RunEventsCallbackHandler(BaseCallbackHandler)`: records start/end/error times, token usage from `llm_output`/`usage_metadata`, tool name + argument KEYS only, retrieval doc ids + scores; redaction: no prompt text, no cell values, no keys unless `log_prompts` is on (then only for the report owner's diagnostics).
- Also counts LLM calls against the global daily cap (`auth.limits.consume(KIND_LLM_CALL…)`) before each call; cap reached → `LimitExceeded` surfaces as a friendly error.
- Tests: events written with timings/tokens; no raw values in `detail`; cap enforcement blocks a call.

## Task 6 — Unknown-column guard (`llm/guards.py`)
- `check_unknown_columns(draft, undocumented: set[str]) -> list[str]` — violations if prose mentions an undocumented column name (case-insensitive, word-boundary) without it being in `unknown_columns_acknowledged`, or interprets it (any claim citing an observation from that column).
- Feeds the M7 revise loop alongside the M4 verifier feedback.
- Tests with the `val_adj_x` demo column.
